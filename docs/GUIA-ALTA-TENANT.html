Arquitectura multi-tenant

RojoPlus usa una única base de datos PostgreSQL compartida por todos los clubes. Cada registro de negocio lleva una columna tenant_id que lo ata al club dueño. El middleware extractTenant identifica al club por el subdominio del host y rechaza cualquier petición de un tenant inactivo o suspendido.

1

Crear el tenant

Hay dos formas de crear un tenant. La recomendada en producción es desde el Panel Super-Admin.

Opción A — Panel Super-Admin (recomendada)

  1. Acceder al panel en localhost:5173/super-admin (dev) o clubix.com.ar/super-admin (prod).
  2. Ir a Tenants → Nuevo Tenant.
  3. Completar el formulario con los datos del club. El campo Subdominio es crítico: solo letras minúsculas, números y guiones (^[a-z0-9-]+$). Ejemplos: sportivopilar, club-atletico-rio.
  4. Guardar. El tenant queda en estado PENDING_APPROVAL con activo = false.

Opción B — SQL directo

INSERT INTO tenants (
  nombre, subdomain, slug,
  email, telefono,
  ciudad, provincia,
  plan, estado, activo,
  timezone, moneda,
  colores, redes_sociales,
  created_at, updated_at
) VALUES (
  'Club Ejemplo', 'clubejemplo', 'clubejemplo',
  'admin@clubejemplo.com', '011-1234-5678',
  'Buenos Aires', 'Buenos Aires',
  'TRIAL', 'PENDING_APPROVAL', false,
  'America/Argentina/Buenos_Aires', 'ARS',
  '{}', '{}',
  NOW(), NOW()
)
RETURNING id, subdomain; -- Guardar el id para los pasos siguientes
⚠️
Nota sobre el slug: debe ser idéntico al subdomain. El código lo genera automáticamente como subdomain.toLowerCase().replace(/[^a-z0-9-]/g, '-'). Si insertás por SQL, asegurate de que coincidan.

CampoTipoObligatorioDescripción

slugString únicoSíIgual al subdomain (auto-generado)

Crear y vincular el administrador

El admin del club es una fila en la tabla global admins vinculada al tenant via tenant_usuarios.

Opción A — Registro público (crea admin + vínculo automáticamente)

-- Endpoint: POST /api/super-admin/tenants/register
-- Body JSON:
{
  "nombre": "Club Ejemplo",
  "subdomain": "clubejemplo",
  "email": "admin@clubejemplo.com",
  "adminData": {
    "nombre": "Juan Administrador",
    "email": "juan@clubejemplo.com",
    "password": "ClaveSegura123!",
    "nombreUsuario": "juan.admin"
  }
}

Opción B — SQL manual (si el tenant ya fue creado)

-- 1. Crear el admin (password debe ser hash bcrypt)
INSERT INTO admins (nombre, email, password, nombre_usuario, activo, created_at, updated_at)
VALUES (
  'Juan Administrador',
  'juan@clubejemplo.com',
  '$2b$10$...', -- hash bcrypt de la contraseña
  'juan.admin',
  true,
  NOW(), NOW()
)
RETURNING id;

-- 2. Vincular admin al tenant
INSERT INTO tenant_usuarios (tenant_id, admin_id, rol, permisos, activo, fecha_ingreso, created_at, updated_at)
VALUES (
  <TENANT_ID>,    -- id del tenant creado en el paso 1
  <ADMIN_ID>,     -- id del admin recién creado
  'ADMIN',
  '[]',
  true,
  NOW(), NOW(), NOW()
);
⚠️
El campo password debe ser un hash bcrypt ($2b$10$...). Nunca insertar contraseñas en texto plano. Para generarlo desde Node.js: await bcrypt.hash('contraseña', 10)

Roles disponibles en TenantUsuario

RolDescripción
ADMINAcceso completo al tenant
TESOREROSolo módulos financieros
SECRETARIOSocios e inscripciones
CONSULTASolo lectura
ℹ️
Un mismo Admin puede estar vinculado a múltiples tenants con distintos roles. La tabla tenant_usuarios tiene un unique en (tenantId, adminId).
3

Aprobar el tenant

El tenant en estado PENDING_APPROVAL no es accesible. extractTenant rechaza cualquier petición con Club no encontrado o inactivo hasta que se apruebe.

Desde el panel

Super-Admin → Tenants → (seleccionar el club) → botón Aprobar.

Via API

POST /api/super-admin/tenants/{id}/approve
Authorization: Bearer <TOKEN_SUPERADMIN>

SQL directo

UPDATE tenants
SET
  estado = 'ACTIVE',
  activo = true,
  fecha_aprobacion = NOW(),
  updated_at = NOW()
WHERE id = <TENANT_ID>;
✅
Luego de este paso el subdominio clubejemplo.clubix.com.ar ya responde. El admin puede iniciar sesión desde la URL del club.
4

DNS y configuración Nginx

✅
En producción (clubix.com.ar) esto ya está resuelto. El certificado wildcard SSL y el bloque server_name *.clubix.com.ar en Nginx cubren automáticamente cualquier nuevo subdominio. No se requiere ningún cambio de infraestructura para cada nuevo tenant.

Cómo funciona el routing

RequestNginx blockDestino
clubix.com.arSitio institucional/var/www/clubix/web
clubejemplo.clubix.com.arWildcard *.clubix.com.arApp React en /var/www/clubix/client/dist
clubejemplo.clubix.com.ar/api/*Proxy passBackend Node.js puerto 5400

Cómo el backend identifica el tenant

Nginx pasa el header Host: clubejemplo.clubix.com.ar al backend via proxy_set_header Host $host. El middleware extractTenant extrae el subdomain (clubejemplo) y busca el tenant en la DB.

En desarrollo local

# Para probar un tenant localmente editar C:\Windows\System32\drivers\etc\hosts:
127.0.0.1  clubejemplo.localhost

# O usar el header X-Tenant-Slug en las peticiones API:
curl -H "X-Tenant-Slug: clubejemplo" http://localhost:3000/api/admin/socios

Si no hay subdomain en desarrollo, el sistema usa el valor de DEFAULT_TENANT_SUBDOMAIN en el .env del servidor.

Conceptos de tesorería y plan de cuentas

Los conceptos de tesorería clasifican los movimientos de caja. Sin ellos, no se puede cobrar ni registrar egresos. Cada concepto puede vincularse a una cuenta contable y un centro de costo para que los asientos contables se generen correctamente.

-- Reemplazar <T> por el tenant_id real

6.2 — Vincular a tipos de socio (una vez creados los conceptos)

UPDATE tipos_socio
SET
  concepto_tesoreria_id = (SELECT id FROM conceptos_tesoreria WHERE codigo='COB-CUO' AND tenant_id=<T>),
  concepto_mora_id      = (SELECT id FROM conceptos_tesoreria WHERE codigo='ING-MORA' AND tenant_id=<T>)
WHERE tenant_id = <T>;

6.3 — Configurar concepto por defecto

INSERT INTO configuracion (clave, valor, tenant_id, created_at, updated_at)
VALUES
  ('CONCEPTO_COBRANZA_CUOTAS',
   (SELECT id::text FROM conceptos_tesoreria WHERE codigo='COB-CUO' AND tenant_id=<T>),
   <T>, NOW(), NOW()),
  ('CONCEPTO_MORA',
   (SELECT id::text FROM conceptos_tesoreria WHERE codigo='ING-MORA' AND tenant_id=<T>),
   <T>, NOW(), NOW())
ON CONFLICT (clave, tenant_id) DO UPDATE SET valor = EXCLUDED.valor;
⚠️
Sin CONCEPTO_COBRANZA_CUOTAS configurado, el sistema no puede generar cargos de cuotas. Es un prerequisito para cualquier flujo de cobranza.

8.2 — Crear Actividades

Desde el panel: Deportes → Actividades → Nueva Actividad

INSERT INTO actividades (
  codigo, nombre, activo, orden,
  concepto_tesoreria_id, concepto_mora_id, centro_costo_id,
  tenant_id, created_at, updated_at
)
SELECT
  a.codigo, a.nombre, true, a.orden,
  ct_cob.id, ct_mora.id, cc.id,
  <T>, NOW(), NOW()
FROM (VALUES
  ('FUT', 'Fútbol',   1, 'FUT'),
  ('BAS', 'Básquet', 2, 'BAS'),
  ('VOL', 'Vóley',   3, 'VOL'),
  ('NAT', 'Natación',4, 'NAT'),
  ('HOC', 'Hockey',  5, 'HOC'),
  ('TEN', 'Tenis',   6, 'TEN'),
  ('PAD', 'Paddle',  7, 'PAD'),
  ('GIM', 'Gimnasia',8, 'GIM')
) AS a(codigo, nombre, orden, cc_codigo)
JOIN conceptos_tesoreria ct_cob  ON ct_cob.codigo='COB-ACT' AND ct_cob.tenant_id=<T>
JOIN conceptos_tesoreria ct_mora ON ct_mora.codigo='ING-MORA' AND ct_mora.tenant_id=<T>
JOIN centros_costo cc            ON cc.codigo=a.cc_codigo AND cc.tenant_id=<T>;

8.3 — Crear Categorías por Actividad

Cada actividad necesita al menos una categoría con su cuota mensual.

Desde el panel: Deportes → (seleccionar actividad) → Categorías → Nueva

-- Ejemplo para Fútbol con 3 categorías
INSERT INTO categorias_actividad (
  codigo, nombre, cuota_mensual,
  actividad_id, tenant_id, created_at, updated_at
)
SELECT
  c.codigo, c.nombre, c.cuota,
  a.id, <T>, NOW(), NOW()
FROM (VALUES
  ('INF', 'Infantil',  5000.00),
  ('JUV', 'Juvenil',   7000.00),
  ('ADU', 'Adultos',   9000.00)
) AS c(codigo, nombre, cuota)
CROSS JOIN actividades a
WHERE a.codigo='FUT' AND a.tenant_id=<T>;

Verificación final

Checklist antes de habilitar al club

  • Tenant creado con activo = true y estado ACTIVE
  • Admin vinculado en tenant_usuarios
  • Login desde subdominio.clubix.com.ar funciona
  • Tipos de socio cargados (al menos 1)
  • Estados de socio cargados (VIGENTE es el mínimo)
  • Conceptos de tesorería cargados (COB-CUO e ING-MORA como mínimo)
  • Clave CONCEPTO_COBRANZA_CUOTAS configurada
  • Medios de pago cargados (Efectivo es el mínimo)
  • Al menos una actividad con una categoría (si el club tiene deporte)
  • Caja principal creada (Tesorería → Cajas)

Test de smoke end-to-end

  1. Crear un socio desde Panel Admin → Socios → Nuevo Socio
  2. Registrar un cargo manual de cuota social
  3. Cobrar el cargo → verificar que se genera el movimiento de caja
  4. Verificar que el socio puede acceder al portal (subdominio.clubix.com.ar/s/{token})
  5. Si el club tiene buffet: crear un producto, abrir una mesa, agregar ítem y cobrar

Query de verificación rápida

-- Estado del tenant
SELECT
  t.id, t.nombre, t.subdomain, t.estado, t.activo,
  (SELECT COUNT(*) FROM tipos_socio     WHERE tenant_id=t.id) tipos_socio,
  (SELECT COUNT(*) FROM estados_socio   WHERE tenant_id=t.id) estados_socio,
  (SELECT COUNT(*) FROM conceptos_tesoreria WHERE tenant_id=t.id) conceptos_tes,
  (SELECT COUNT(*) FROM medios_pago     WHERE tenant_id=t.id) medios_pago,
  (SELECT COUNT(*) FROM actividades     WHERE tenant_id=t.id) actividades,
  (SELECT COUNT(*) FROM tenant_usuarios WHERE tenant_id=t.id) admins
FROM tenants t
WHERE t.subdomain = 'clubejemplo';

Script SQL de arranque completo

Script para insertar todos los datos mínimos de un tenant nuevo en una sola pasada. Reemplazar <T> por el tenant_id real luego de crearlo.

🚨
Ejecutar este script después de crear el tenant en la tabla tenants y antes de habilitarlo. Verificar que no existan registros previos para el mismo tenant_id.
-- ============================================================
-- SCRIPT DE INICIALIZACIÓN DE TENANT
-- Reemplazar <T> por el tenant_id real en TODOS los lugares
-- ============================================================

DO $$
DECLARE
  v_tenant_id  INT := <T>;
  v_cob_cuo_id INT;
  v_ing_mora_id INT;
  v_cob_act_id INT;
BEGIN

-- 1. TIPOS DE SOCIO
INSERT INTO tipos_socio (codigo, nombre, orden, activo, tenant_id, created_at)
VALUES
  ('ACTIVO', 'Socio Activo', 1, true, v_tenant_id, NOW()),
  ('CADETE', 'Socio Cadete', 2, true, v_tenant_id, NOW()),
  ('VITALICIO', 'Socio Vitalicio', 3, true, v_tenant_id, NOW())
ON CONFLICT (tenant_id, codigo) DO NOTHING;

-- 2. CATEGORÍAS DE SOCIO

Agente de Impresión (Print Agent)

El print-agent es un proceso Node.js que corre en cada puesto de impresión (barra, cocina, caja) y recibe los trabajos de impresión desde el servidor via WebSocket. Soporta impresoras USB, CUPS y red (IP/TCP).

ℹ️
Las variables de entorno clave son: ROJOPLUS_SERVER_URL, ROJOPLUS_PRINT_TOKEN, ROJOPLUS_PUESTO_ID y ROJOPLUS_PUESTO_NOMBRE.

Instalación en Linux (Ubuntu/Debian)

Opción A — Script automático (recomendado)

Copiá la carpeta print-agent/ al puesto y ejecutá:

cd print-agent
sudo ./install.sh

El script instala Node.js si no está, copia los archivos a /opt/rojoplus-print-agent, solicita los datos de configuración interactivamente y registra el servicio en systemd.

Opción B — Instalación manual

# 1. Crear directorio e instalar
sudo mkdir -p /opt/rojoplus-print-agent
sudo cp index.js package.json /opt/rojoplus-print-agent/
cd /opt/rojoplus-print-agent
sudo npm install --production

# 2. Crear el servicio systemd
sudo nano /etc/systemd/system/rojoplus-print-agent.service

Contenido del archivo .service:

[Unit]
Description=RojoPlus Print Agent
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/rojoplus-print-agent
ExecStart=/usr/bin/node /opt/rojoplus-print-agent/index.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=rojoplus-print-agent

Environment=NODE_ENV=production
Environment=ROJOPLUS_SERVER_URL=https://miclub.clubix.com.ar
Environment=ROJOPLUS_PRINT_TOKEN=rojoplus-print-agent
Environment=ROJOPLUS_PUESTO_ID=barra-01
Environment=ROJOPLUS_PUESTO_NOMBRE=Barra

[Install]
WantedBy=multi-user.target
# 3. Habilitar y arrancar
sudo systemctl daemon-reload
sudo systemctl enable rojoplus-print-agent
sudo systemctl start rojoplus-print-agent

# 4. Verificar
sudo systemctl status rojoplus-print-agent

Permisos USB en Linux

# Crear regla udev para acceso a USB sin root
sudo nano /etc/udev/rules.d/99-usb-printer.rules
SUBSYSTEM=="usb", ATTR{idVendor}=="*", MODE="0666"
KERNEL=="lp[0-9]*", MODE="0666"
sudo udevadm control --reload-rules
sudo udevadm trigger

Instalación en Windows

  1. Instalar Node.js
    Descargar e instalar Node.js 20 LTS desde nodejs.org. Verificar con node --version en CMD.
  2. Copiar archivos
    Copiar la carpeta print-agent\ a C:\rojoplus-print-agent\ e instalar dependencias: 
    cd C:\rojoplus-print-agent
npm install --production
  3. Crear archivo de configuración
    Crear el archivo C:\rojoplus-print-agent\.env (o usar variables de entorno del sistema): 
    ROJOPLUS_SERVER_URL=https://miclub.clubix.com.ar
ROJOPLUS_PRINT_TOKEN=rojoplus-print-agent
ROJOPLUS_PUESTO_ID=caja-01
ROJOPLUS_PUESTO_NOMBRE=Caja
  4. Instalar como servicio Windows con NSSM
    Descargar NSSM y ejecutar como Administrador: 
    nssm install RojoPlusPrintAgent
# En el cuadro de diálogo:
#   Path:    C:\Program Files\nodejs\node.exe
#   Startup: C:\rojoplus-print-agent
#   Arguments: index.js

nssm start RojoPlusPrintAgent
  5. Alternativa sin NSSM — ejecutar manualmente 
    cd C:\rojoplus-print-agent
node index.js
    Para que arranque solo con Windows, crear un acceso directo en la carpeta shell:startup.

Windows

# Opción A: editar variables de entorno del sistema y reiniciar el servicio
nssm stop RojoPlusPrintAgent
# (editar .env o variables de entorno del sistema)
nssm start RojoPlusPrintAgent

# Opción B: reconfigurar con NSSM
nssm edit RojoPlusPrintAgent
✅
Al reconectar correctamente verás en los logs: [PrintAgent] Conectado via Socket: <puesto-id>

Verificar que el puesto está conectado

Desde el admin del sistema: Buffet → Impresoras → Puestos conectados. El puesto debe aparecer con estado verde.

⚠️
Si el trabajo se encola ("Trabajo enviado a puesto:xxx") pero no imprime, el puesto no está conectado al WebSocket. Verificar URL, token y que el servicio esté corriendo.
